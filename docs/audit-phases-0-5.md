## 5. Defects found and fixed during this audit

**F-1 (medium): trade parser silently converted a negated margin into a positive size.**

- Observed: `parseTradeIntent('long rNVDA over the weekend at 3x with -5000 USDT')` returned ok with `sizeUsdt: 5000`. The size regex captures digits only, dropping the sign.
- Expected: fail-closed refusal (`PARSE_UNCERTAIN`), per the plan's "never silently zero/coerce" rule.
- Root cause: `extractSize` patterns capture unsigned digit groups; no sign guard existed.
- Impact: low for the demo UI (free-text negative margin is unusual) but it violates the product's own fail-closed contract, and validateParsedTrade never saw the sign.
- Fix: fail-closed guard in `extractSize` requiring unit adjacency (`-5000 USDT`, `-$5,000`, `- 5,000 USDT margin` refuse; `9-5` ranges and distant year ranges do not trigger false positives — verified by targeted regex probes).
- Regression tests: `web/tests/domain/parser-negative-size.test.ts` (3 tests: primary form, alternate formats, golden positive inputs still parse).
- Verification after fix: full suite 168/168, tsc 0, build green, demo:verify green, golden sentence still parses.

**F-2 (low): buildDossier silently omitted the liquidation metric when an invalid leverage (<= 1) reached the engine.**

- Observed: calling `buildDossier` directly with `leverage: 0.5` (bypassing `validateParsedTrade`) produced `liquidationDistancePct: null` with `refusal: null` — a silent partial dossier.
- Expected: a refusal state, per the plan's "refusal instead of fabricated/omitted values" rule.
- Root cause: the liquidation branch required `parsed.leverage > 1` but the else path recorded nothing.
- Fix: `dossier-builder.ts` now records a `PARSE_UNCERTAIN` refusal (`Leverage X is invalid for stress computation (must be > 1)`) when leverage <= 1 reaches the engine.
- Regression tests: `web/tests/engine/dossier-builder-leverage-guard.test.ts` (3 tests: 0.5 refuses, exactly 1 refuses, valid leverage builds clean).
- Verification: suite green after fix.

**F-3 (cleanup): dead `PlaceholderCard` component removed; landing CSS `#fff` x3 replaced with `--br-text-inverse` token; stale `TEST_COUNT` constant (165, actual 171) removed from landing source rather than mirrored.**

## 6. Non-defect observations (documented, no action now)

- **Registry `Date.now()` id input:** `registerForecast` mixes `Date.now()` into the hash, so ids are not reproducible across runs. Acceptable for the in-memory registry; if fixtures ever embed registry-generated ids, switch to `hashTrade` for determinism. The replay fixtures already use stable date-derived ids, so no action.
- **Funding carry unit convention:** `computeFundingCarry` multiplies by 100 internally; callers must pass the raw fraction (0.000219 → 0.16425%). Consistent across normalizers/engine; noted for future contributors.
- **Overview demo candles:** non-NVDA "regime demo candles" are deterministic synthetic sequences (clearly commented in `components/dossier/fixtures.ts`); all history *stats* come from real per-asset fixtures. Distinction is documented rather than hidden.
- **Live funding can legitimately be 0:** Bitget clamps stock-perp funding; a 0.00% carry display is truthful, not a bug.
- **lint script is a placeholder echo** (no eslint dependency by design). Typecheck + tests + build are the enforced gates.
- **README.md modified but uncommitted** at audit time; entire working tree (10 phases of work) still unpushed — flagged separately as an operational risk, not a code defect.
